## 3. BUG-001 联系表单错误提示重复堆叠

### 3.1 复现步骤

1. 访问前台「联系我们」页面
2. 直接点击「提交留言」（不填任何内容）→ 各字段下方出现 1 条错误提示（正确）
3. **不修改内容，再次点击「提交留言」** → 错误提示变为 2 条
4. 反复点击，错误提示持续叠加（联系电话字段最多出现 4 条）
5. 错误提示一旦生成，不会自动消失

### 3.2 期望行为

- 每次提交（或输入）时，字段下方**只显示 1 条**最新错误提示
- 用户开始修改字段后，该字段错误提示立即消失（即时校验）
- 错误提示不可累积堆叠

### 3.3 实际行为（见截图 `clipboard-2026-08-26T17-08-20-235Z-a34313a6.png`）

- 姓名下 1 条、联系电话下 **4 条**、留言内容下 **2 条**、验证码下 1 条
- 错误条反复追加、无清除逻辑

### 3.4 根因分析

前端校验逻辑在失败时**只 append 错误元素（.err），未清空旧错误**。

参考原型实现（`前台官网原型.html` 第 1721–1733 行）——原型在每次提交前**先清除全部旧错误**再校验：

```javascript
form.addEventListener('submit', function(e){
  e.preventDefault();
  // ... 读取字段值
  const errs = document.querySelectorAll('.field .err');
  errs.forEach(x=>x.remove());   // ← 关键：先清空旧错误（React 实现疑似遗漏）
  let ok = true;
  function fail(input, text){ /* append 1 条错误 */ }
  ...
});
```

### 3.5 修复指引

React 实现要求（与 UI/UX 文档 §5.6 表单规范对齐）：

1. **错误提示由 state 派生，禁止直接操作 DOM 追加**：
   ```javascript
   const [errors, setErrors] = useState({});   // { name:'', phone:'', msg:'', captcha:'' }
   // 每次校验整体覆盖 setErrors({...})，UI 上：{errors.phone && <p className="err">请输入 11 位有效手机号</p>}
   ```
2. **onChange 即时校验**：用户开始修改某字段时，清除该字段的旧错误（输入即消失）
3. 提交时统一校验 4 个字段（规则见 UI/UX 文档 §5.6 / API 契约 §3.5），全部通过才发请求
4. **验证码错误（API 40002）需刷新图形验证码**，并保留"验证码错误，请重新输入"提示
5. 提交成功后：清空表单 + 显示成功提示"提交成功，我们会尽快与您联系"（4s 自动消失）

### 3.6 验收标准

- [ ] 连续点击提交 N 次，每个字段下方错误提示始终只有 1 条
- [ ] 修改字段内容后，该字段错误提示立即消失
- [ ] 错误提示文案与 UI/UX 文档 §5.6 完全一致（姓名 2-20 字 / 手机号 11 位 / 留言 1-500 字 / 验证码 4 位）
- [ ] 验证码输错 3 次，验证码图每次都会刷新
- [ ] 4 个字段全部合法时提交成功，出现成功提示条且表单清空

## 4. BUG-002 蛋糕展示排序功能失效

### 4.1 复现步骤

1. 访问前台「蛋糕展示」页面
2. 右上角排序下拉选择「价格 低到高」
3. 观察产品网格顺序

### 4.2 期望行为

- 选择「价格 低到高」后，产品按起价（price_from）**升序**排列
  - 例：焦糖栗子磅蛋糕 ¥158 → 醇香红丝绒 ¥168 → 草莓奶油 ¥168 → 经典芝士 ¥178 → 黑巧熔岩 ¥188 → 宇治抹茶慕斯 ¥198 …
- 选择「价格 高到低」后降序；「新品优先」按创建时间倒序；「推荐」为默认排序（sort_order 升序 → created_at 倒序）
- 切换排序后**回到第 1 页**（UI/UX 文档 v1.1 §5.3 已确认规范）

### 4.3 实际行为（见截图 `clipboard-2026-08-26T17-08-20-237Z-982a5940.png`）

- 选择「价格 低到高」后，产品顺序**未发生任何变化**（¥158 的焦糖栗子磅蛋糕仍排在 ¥168、¥198 之后，仍为默认 sort_order 顺序）
- 下拉显示值已切换，但列表未重排 → 判定 onChange 未绑定或排序逻辑未实现

### 4.4 根因分析

排序下拉 `<select>` 的变更事件未触发列表重排。两种可能：

1. **onChange 未绑定**：只改了 UI 显示值，未 setState / 未重新请求
2. **排序逻辑缺失**：拿到 sort 值后没有对数据排序（前端本地排序或请求参数均未实现）

参考 API 契约 §3.1：

```
GET /api/cakes?category_id=&page=&page_size=12&sort=price_asc
sort 取值：recommend(默认) / price_asc / price_desc / newest
```

### 4.5 修复指引

按 UI/UX 文档 §5.3（v1.1 已确认：排序本期实现）执行：

1. select 绑定 `onChange`，将排序值写入 state（`sort`）
2. **推荐服务端排序**：将 `sort` 作为请求参数传给后端 `GET /api/cakes`，由后端按规则排序返回（与分类筛选、分页联动）
3. 若采用前端排序：用 `useMemo` 依赖 `[products, sort]` 重排数组（price_asc → 按 price_from 升序；price_desc → 降序；newest → 按 created_at 倒序；recommend → 默认 sort_order）
4. **切换排序时重置 `page = 1`**
5. 排序切换与分类筛选叠加使用时，两者条件需同时生效（排序作用于当前分类的结果集）
6. 列表加载中显示 loading 态，禁止白屏

### 4.6 验收标准

- [ ] 「价格 低到高」→ 起价升序；「价格 高到低」→ 降序；「新品优先」→ 新到旧；「推荐」→ 默认排序
- [ ] 排序切换后回到第 1 页
- [ ] 排序与分类筛选联动正常（先选分类再排序 / 先排序再选分类结果一致）
- [ ] 切换排序时列表无闪烁白屏（有 loading 反馈）
