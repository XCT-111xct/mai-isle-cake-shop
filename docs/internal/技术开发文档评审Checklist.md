## A. 文档内部一致性

- [ ] A1 章节交叉引用编号**真实存在**（`grep "见 x.y.z"` 逐条验证，本例曾出现"见 4.2.4"指向不存在的子节）
- [ ] A2 图表编号、表编号与正文引用一一对应（E-R 图、状态机图、架构图）
- [ ] A3 接口总数与附录速查表一致（正文 7 个前台 + 40 个后台 = 47，逐条核对）
- [ ] A4 每次修订更新版本号 + 变更记录（留痕，v1.0 → v1.1 示例）
- [ ] A5 代码块全部闭合（`grep -c '^```'` 为偶数）；Mermaid 块可正常渲染
- [ ] A6 术语统一（snake_case、路径命名、错误码文案前后端一致）

## B. 数据库设计

- [ ] B1 **SQLite 外键默认关闭**——必须显式 `PRAGMA foreign_keys=ON`（SQLAlchemy 用 `@event.listens_for(engine,"connect")`），否则 `ON DELETE CASCADE` 与外键校验**静默失效** ← 最易漏
- [ ] B2 表名 / 列名避开 SQL 保留字（如 `ORDER` 保留，`orders` 安全）
- [ ] B3 金额列用 `NUMERIC(10,2)` + Python `Decimal` 计算，禁止 float 参与乘除（0.1+0.2 类精度误差）
- [ ] B4 唯一约束与重名冲突错误码配套（DB UNIQUE 兜底 + 40900 业务提示）
- [ ] B5 CHECK 约束枚举与业务状态机完全一致（订单状态、角色、取货方式）
- [ ] B6 索引覆盖查询路径（外键列、状态筛选列、排序列、created_at 倒序）
- [ ] B7 种子数据幂等（已存在跳过）；初始化文案与 PRD 一致（品牌故事/历程/订购信息）
- [ ] B8 无 Alembic 迁移工具时，补充表结构变更流程与"上线改动先备份"要求

## C. 接口设计

- [ ] C1 REST 语义正确：**DELETE 不带请求体**（代理/网关会剥离，改用 Query 参数，如 `?move_to_id=2`）；PATCH 做局部更新
- [ ] C2 分页参数统一（`page` / `page_size` / `total` / `total_pages`，默认 1/12）
- [ ] C3 错误码表完整且前后端一致（40001/40002/40100-40103/40300/40400/40900/50000 + HTTP 状态码映射）
- [ ] C4 敏感字段脱敏规范明确（列表脱敏 `138****6321` / 详情完整，仅限有权限后台）
- [ ] C5 每个接口标注鉴权等级（无需登录 / 登录 / 超管）
- [ ] C6 多表写操作事务边界清晰（商品+规格、分类迁移，任一失败整体回滚）
- [ ] C7 并发边界已处理（订单号当日自增、上传文件名 uuid 防同秒覆盖、验证码一次性校验）
- [ ] C8 接口字段 ↔ 数据库列映射完整（请求/响应示例与表结构逐字段核对）
- [ ] C9 **"建议中/待定"的接口不能悬空**——要么定稿进参数表，要么删除（本例 `featured=1` 由建议改为定稿）

## D. 后端实现

- [ ] D1 统一响应封装 + 全局异常处理器（BizError → code/message/data）
- [ ] D2 认证依赖注入 + 权限双重拦截（前端隐藏菜单仅体验，后端必须校验 40300）
- [ ] D3 JWT 无状态边界写清楚：后端 exp 固定，滑动过期由前端拦截器实现
- [ ] D4 登录锁定持久化（DB 字段 `failed_attempts`/`locked_until`，非内存）
- [ ] D5 密码哈希库版本兼容（passlib 1.7.4 搭配 bcrypt ≥4.1 有告警 → 固定 4.0.x）
- [ ] D6 上传安全：类型/大小白名单、文件名重写防路径穿越

## E. 前端实现

- [ ] E1 路由守卫齐全（未登录重定向 /login；超管路由 RequireSuper）
- [ ] E2 表单错误由 state 派生、整体覆盖、onChange 清除（防堆叠，BUG-001 类）
- [ ] E3 筛选/排序/分页联动（onChange 绑定、切换重置 page=1、loading 态防白屏，BUG-002 类）
- [ ] E4 样式对齐 Design Token（CSS Variables 全局变量，禁止硬编码色值）
- [ ] E5 无障碍：label for / alt / focus-visible 焦点环 / prefers-reduced-motion
- [ ] E6 响应式断点完整（980px 汉堡菜单、640px 表单单列、表格不暴力换行）

## F. 部署与运维

- [ ] F1 **单机依赖与 worker 数自洽**：SQLite 单写 + 验证码内存缓存 → 必须单 worker（多 worker 会锁库/验证码跨进程失效）← 本例踩坑
- [ ] F2 静态资源 / uploads / 数据库文件持久化（容器部署挂 volume，防重建丢失）
- [ ] F3 CORS 白名单（仅正式域名 + 本地端口）、HTTPS、JWT 密钥走环境变量
- [ ] F4 备份策略（SQLite 单文件直接拷贝 + uploads 目录）
- [ ] F5 SPA 路由回退（Nginx `try_files ... /index.html`）

## G. 安全

- [ ] G1 全部参数化查询（SQLAlchemy），禁止字符串拼接 SQL
- [ ] G2 富文本渲染禁用 rawHtml（react-markdown 默认转义即可）
- [ ] G3 初始密码（如 admin123）部署后必须修改的提示
- [ ] G4 验证码一次性（校验即删）+ 5 分钟过期

## H. 业务规则一致性

- [ ] H1 状态机合法流转表 + 后端强制校验（非法流转返回 40001 及说明）
- [ ] H2 快照机制（订单存规格价格快照，产品改配置不影响历史订单）
- [ ] H3 金额自动计算、不可手改（后端计算，请求体不接受 amount）
- [ ] H4 特殊保护规则：超管账号不可删、系统至少保留 1 个超管、产品仅下架不删除

## 使用建议

1. **交付前自检**：作者按 A–H 逐条勾选，问题当场修复
2. **评审他评**：换一个人（或架构师视角）按清单再审一遍，重点查 A1、B1、C1、C7、F1 五类"换项目还会再犯"的坑
3. **持续扩充**：每发现一类新问题，追加到对应类别，保持清单活文档状态
4. **与文档模板配合**：新项目写技术文档时，直接把本清单的关键项（B1/C1/C7/F1）预置进文档骨架
